## Priority Issues

[P0] Button.svelte silently defeats the global focus-ring fix from the last pass
- Why it matters: Verified by building the package and inspecting compiled CSS. Svelte's automatic style scoping turns Button.svelte's "button, a { outline: none; }" into "button.svelte-118lylz, a.svelte-118lylz {...outline:none...}" — an element+class compound selector, specificity (0,1,1). The global ":focus-visible { outline: 2px solid var(--color-primary); }" rule added to tokens.css last pass is a bare pseudo-class, specificity (0,1,0). Higher specificity always wins regardless of source order, so Button's outline:none overrides the fix — on the component used on nearly every page of all 8 consumer sites, including this showcase's own homepage CTAs. No other component in src/lib sets outline:none, so this is isolated but high-impact.
- Fix: Remove outline:none from Button.svelte:134, or add an explicit local :focus-visible rule there.
- Suggested command: /impeccable audit

[P1] The showcase reports three different, all-wrong component counts
- Why it matters: Verified directly: src/routes/components/+page.svelte:78 says "96 components," its own per-category count fields sum to 91, and src/lib/*.svelte actually contains 110 files. For a tool whose value proposition is "trust this is current," and whose DESIGN.md has a Ripple-Check Rule asking maintainers to gauge blast radius, none of the three numbers are correct.
- Fix: Derive the count from src/lib/index.ts (or a glob) at build/render time instead of hand-maintained literals.
- Suggested command: /impeccable harden

[P2] Two showcase category links 404 in production
- Why it matters: Carried over from the last critique (out of scope then, now re-verified). svelte.config.js:28 sets base:"/design" for production builds; the components index hardcodes href="/components/interactive" and "/components/media" without the ${base} prefix every other of the 9 category links uses. Confirmed real — these two links break on the deployed site today.
- Fix: Prefix both with ${base}.
- Suggested command: /impeccable harden

[P2] Text-entry inputs have no error/invalid state
- Why it matters: InputText, InputNumber, InputCheckbox expose only border:"transparent"|"solid" — no way to show a bad value — while InfoBox a few files away has a fully-built error variant with --color-danger already wired in from last pass.
- Fix: Add an error?: boolean (+ message) to the three input components, reusing --color-danger.
- Suggested command: /impeccable harden

[P3] Dropdown menus lack aria-expanded/Escape-to-close
- Why it matters: ButtonMenu and CollapseToBurger — both used in the showcase's own primary nav — have no aria-expanded/aria-haspopup on their trigger and no Escape-key handler. ButtonMenu opens on mouseenter/closes on mouseleave with only a click fallback, unreliable for keyboard-only or touch use.
- Fix: Add aria-expanded={open} and a document keydown handler for Escape on both.
- Suggested command: /impeccable audit
